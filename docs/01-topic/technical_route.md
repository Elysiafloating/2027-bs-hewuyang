# 技术方案（technical_route）

> 依据 `技术方案与参考文献建议.docx` V2（曾维老师组，何雾阳专属方案）。
> 方案结构：数据先行 → Baseline → 核心工作 → 实验设计 → 交付物 → 风险与降级。

## 1. 数据先行（开题阶段必须完成）

目前 **star 类 Recall=0.0558**，定位原因是最低要求第一条，开题就要交**数据体检报告**
（`data/metadata/data_health_report.md` 模板）：

- 各类别实例数（meteor / seagull / airplane / satellite / star）
- 目标像素尺寸分布（相对面积、宽高）
- 每图目标数
- 标注一致性抽查（随机 200 个框人工复核）

经验上 star 类极低多半源于：
1. 实例过少
2. 目标小于下采样步长
3. 正负样本分配时几乎取不到正样本
4. 与背景恒星特征混淆

**这三条必须逐一排查并在论文中写明结论。**

## 2. Baseline

- 模型：YOLOv8n / YOLOv8s
- 固定输入分辨率与训练轮数（保证可复现，记录随机种子）
- 记录：整体 mAP@0.5、mAP@0.5:0.95 及分类别 P/R
- 当前 Baseline（YOLOv8n）：整体 mAP@0.5=0.5908，meteor R=0.9365，**star R=0.0558**

## 3. 核心工作（措施顺序：从数据侧走到模型侧，勿一上来换损失）

| 顺序 | 措施 | 说明 |
|---|---|---|
| (1) | 样本量与标注质量 | 先解决数据侧根因（star 过采样、难例挖掘） |
| (2) | 目标尺寸统计与输入分辨率 | 针对 star 等弱小目标 |
| (3) | 增加 P2 小目标检测头 | 提升小目标特征 |
| (4) | 类别不平衡与采样策略 | 解决 star 与其他 4 类的不平衡 |
| (5) | 最后才考虑标签分配 / 损失 | 含 NWD（见下方注意） |

**NWD 特别注意**：该方法原本为 anchor-based 检测器替换基于 IoU 阈值的标签分配
（NWD-RKA）而提出；**YOLOv8 是 anchor-free 结构**，直接把损失替换进去不一定合理。
若要用，必须说明如何适配并给出对比数据。

**虚警抑制**：seagull、airplane、satellite 与 star 均为虚警来源；后处理加时序 / 形态学约束
（流星为线状短时目标，恒星静止；飞机/卫星轨迹有规律，海鸥轨迹短促）。
**选定两种措施分别实现、分别评估，效果为负也如实写。**

## 4. 实验设计

- 主表按类别报告 P、R、mAP@0.5、mAP@0.5:0.95，并**单列虚警率**（每帧误检数或 FPPI）
- 消融覆盖两种措施的单独与组合
- 错误案例分漏检、虚检两组，各选 3~5 张图做可视化分析
- 注明单次运行还是多次平均

## 5. 交付物

- 数据体检报告
- 训练配置（`configs/`）
- 权重（Release 分发，不入库）
- 推理与评测脚本（`src/`）
- 可视化结果（`results/figures/`）

## 6. 主要风险与降级方案

- **指标能否翻盘不完全可控** → 论文价值点放在“失效原因的定位与验证”上，
  绪论和结论都按这个逻辑写。
- **数据量不足** → 补数据或数据合成须在 **10 月前**决定，否则来不及重训。
- 时间/设备受限时的退路：保证“定位原因 + 两种措施 + 如实报告”闭环，
  而非追求指标。
